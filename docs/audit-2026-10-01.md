# End-to-end audit — 1 October 2026

## Verdict

Every Go package, the services and bridge contract, the whole Vue frontend,
the migrations, the docs and the build configuration were reviewed, as of
`a253a45` (schema v15, Places, Events and blocking). The review found one
production-only P1 bug that no earlier audit or test had caught. It found no
other P1 in the engine. There were real P2 bugs in blocking, clustering,
search, the indexing pipeline, media decoding and the grid's keyboard
handling, plus duplicated rules and stale state and docs.

The fixes are in the working tree, uncommitted. The full lint gate is clean.
The Go race suite passes, and so do the three face tests that need a real
photo corpus, which earlier audits had to skip. All 62 frontend tests pass.
The bindings have no drift. `wails3 build` passes. A native WebView2 run on
a library upgraded from schema 15 passes every scripted check.

## The production-only bug

**P1: no error code ever reached the UI in the built app.** Wails v3
beta.26 gives each bound method only its service's error marshaller, falling
back to its own. `application.Options.MarshalError` is never used for method
errors. So every coded failure arrived as `{"cause": {}}`:

- `person_exists`: "same person?" never offered a merge.
- `blocked_name`, `invalid_album` and the others: each showed as
  "Something went wrong: …" in engine English.

Unit tests couldn't see it. The frontend tests mock errors with a `cause`,
and `contract_test.go` calls `MarshalError` directly.

- **Fix:** `main.go` registers every service through `service()`, which sets
  `ServiceOptions.MarshalError`.
- **Test:** `TestServiceErrorsCarryTheirCodes` goes through Wails' own
  `Bindings`. It fails without the fix, with `cause = {}`, exactly as the live
  app showed.
- **Seen live:** the Network domain showed the fixed app returning the coded
  `invalid_pin`, and the Blocked screen now says "That PIN isn't right."

## Fixed

### Blocking and visibility

- **A label-only place block still named events.** `groupEvents` read every
  place, so the event title and `placeId` still leaked a place blocked
  label-only. It now reads only unblocked places.
- **Clustering could move a block onto someone else.** Automatic merges could
  fold a blocked person into an unblocked one, so the block moved to them.
  People blocked by the user now count as confirmed, and `ApplyClusters`
  never merges them away.
- **`TagByName` ignored blocks.** Tagging or creating a Thing with a blocked
  Thing's name applied the blocked tag, or revealed that it exists. It now
  returns `blocked_name`.
- **Search: a blocked short name hid a visible longer one.** A blocked "Ali"
  hid a visible "Ali Khan". Blocked and visible names are now matched in one
  pass, so the longer name wins either way.
- **Timelines didn't refresh when a new tag or face put a photo under a
  block.** Migration 0016 adds a visibility-only revision. The indexer reports
  an asset change whenever that revision moves.
- **Search rebuilt its exclusion set far too often.** It followed
  `event_revision`, which every metadata and thumbnail batch bumps, so
  indexing rebuilt the set on each search. It now follows the new revision.
  The block triggers now fire only for changes a block can see: a face with a
  person, a tag that a block names, and so on.
- **Errors without codes.** Block and PIN failures now have codes on both
  sides, checked by the contract test: `invalid_pin`, `pin_exists`,
  `pin_rate_limited`, `blocks_locked`, `undo_expired` and `invalid_block`.
  The PIN length bounds are mirrored and checked too.
- **Re-blocking something already blocked needed the PIN.** Asking for the
  same mode again is now a no-op success.
- **The unlocked Blocked list could stay open.** It stayed open until the view
  unmounted, so a reload left it unlocked. It now relocks after 10 idle
  minutes.
- **Block changes skipped the indexer's reporting.** They now go through the
  indexer's once-a-second change reporting.
- **Lists showed blocked items until they reloaded.** After a block or Undo,
  every loaded list (Things, People, Albums) now reloads with the grid
  (`showBlocksChanged`).
- **One tag threshold everywhere.** The Go and SQL thresholds now compare the
  same `float64`. Before, a score at exactly the threshold counted in a Thing's
  view but not under its block. The SQL default comes from
  `core.TagConfidenceDefault`.
- **One builder for the base visibility clause,** instead of three copies.
- **Block subqueries no longer collide with the caller's aliases.** They use
  their own (`blk_*`).
- **Folder blocks call Go's `fold()` only for non-ASCII paths** (`foldKey`).
- **About 20 inline "is this label blocked" subqueries** became
  `labelBlocked`.

### Store

- **Settings cache race.** A read that raced a write could leave the cache
  stale. Reads now use `LoadOrStore`, and writes are serialised.
- **`tx()` now always rolls back, even on panic,** so the single writer
  connection is never left inside a transaction.
- **`RemoveSource` no longer scans every asset.** It marks orphans only for
  the files it deletes (`RETURNING`).
- **Places:** one cover subquery per place instead of two.
- **Timeline filters:** the place filter now checks the place exists without
  counting its assets.
- **Dead `hidden` state removed.** `Person.Hidden` was always false, and
  `Tag.Hidden` meant only the internal sink. Both are gone from the wire types,
  Things are filtered in SQL, and a built-in's `hidden` follows `is_sink`
  instead of sticking once set.
- **Smaller fixes:**
  - `PeopleAssets` handles repeated ids.
  - `DayItems` never returns nil.
  - The job predicate `blocked` is now `heldBack`, so it no longer shares
    the blocking feature's name.
  - The stale comments are fixed.

### Indexing and AI

- **Short videos wasted model runs.** The image model has a fixed batch of
  16, and each video ran on its own, so a 10 s clip cost a 16-slot run.
  Photos and video frames now fill shared batches (`modelBatch`), holding at
  most one batch of inputs.
- **A face-model failure used to fail every file one by one,** using up
  their retries. Now it fails the batch and backs off. A database failure no
  longer frees the models or shows up as an AI error. A failed save is
  retried before the batch is processed again.
- **New thumbnails now re-queue the embedding.** The image model reads the
  thumbnail, so an upgraded thumbnail must be embedded again.
- **A Thing created during indexing could miss up to a batch of photos.**
  Now `search.Engine.Commit` orders index saves with a Thing's re-scoring,
  and re-tags a batch that was tagged under older Things.
- **A failed search engine load was permanent until restart.** It is now
  retried with backoff. Reloading the video index no longer duplicates
  frames.
- **Relearning a user's Thing no longer re-tags the whole library;** it
  scores that Thing alone. Its vectors are stored only after scoring
  succeeds, so an interrupted load learns it again.
- **Face detector:** a NaN score or box is dropped instead of panicking
  later. Small images no longer get a black first row and column when
  enlarged.
- **Clustering stops on shutdown** (it now takes a `ctx`).
- **Stale neighbour links.** The Linker notices face vectors rewritten in
  place, which happens when a photo is looked at again.
- **`OddOnesFirst` uses the vector length most faces have,** during a face
  model upgrade.
- **Watcher goroutines are tracked by `Stop`.**
- **Smaller fixes:**
  - The thumbnail upgrade rule parses its version with `CutSuffix`.
  - Prompt vectors use `ai.Normalise`.
  - The search cut's comment now says "odds"; its behaviour is unchanged.

### Media, scanner and main

- **HEIC decoded by FFmpeg kept its Display P3 colours.** This affects PCs
  without the HEVC extension.
  - **Fix:** libvips reads the profile from the HEIC header, and `vips.Pixels`
    carries it to `to_srgb8`.
  - **Version bump:** `ThumbnailVersion` is now `vips-8.18-3`. The upgrade
    rule keeps every thumbnail except HEIC in a profile other than sRGB.
- **A missing `ffmpeg.exe` failed every job** instead of skipping it.
- **Originals were opened without delete sharing,** so a paused video in the
  viewer stopped Explorer moving the file. `core.OpenShared` fixes this.
- **The cache sweep raced the first thumbnail writes.** It now runs before
  indexing starts.
- **Hiding or showing a folder in Explorer is now noticed** (attribute
  changes, `scanner.Exclusion`).
- **A video whose keyframe pass found no frame now gets its first sample.**
- **Relative `LUMEN_*` paths are made absolute.**
- **Startup failures show a message box.**
- **The log now rotates during a session,** not only at startup.
- **One date-plausibility rule** covers photos and videos. It rejects
  unset-clock epochs and keeps pre-1970 scans.
- **A second launch focuses the window itself,** even before it was first
  activated.
- **Scratch libraries** (`LUMEN_DATA_DIR`) get their own single-instance ID
  and their own WebView2 data folder. Found live: WebView2 refused a second
  instance started with other options (`0x8007139f`). Scratch libraries also
  no longer share localStorage or the HTTP cache with the user's.
- **Other cleanups:**
  - `VideoFramesVersion` moved into `media`, beside the sampling code it
    versions.
  - The two extension tables were merged, and `Changes.Any/Merge` removed.
  - The eviction comments no longer describe a size cap that doesn't exist.
  - `testenv.File` skips only for the missing file.

### Services and bridge

- **Adding an already-covered folder did nothing and said nothing.** It now

- **Superseded reads are cancelled in the engine.** `days`, `timeline` and

- **When the video server can't start, the viewer says so** instead of

- **Smaller fixes:**

## Follow-Up: Remaining Eight Issues

All eight remaining limitations from the original audit were addressed in the follow-up working-tree
changes. The earlier verification table describes the original audit run;
the follow-up checks below cover the resulting implementation.

- **Shared video AI decoding.** One coordinator fetches the union of runnable
  video embedding and face jobs, in capture-time order with on-screen work
  first. Both consumers use one streaming sampler at a consistent 2048 px,
  retaining only the current decoded frame and one bounded model-input batch.
  Successful stages are saved independently when another model fails. Photo
  workers cannot race a shared model's inference or unload; embedding batches
  carry their own label-generation snapshots.
- **Kind-specific AI versions.** Photo and video stage versions are separate.
  A transactional upgrade adopts unchanged legacy photo versions without
  processing or rewriting their output. Real photo/model changes still rerun
  the affected stage.
- **Sampler version bump.** `VideoFramesVersion` is now `+video-frames-2`.
  Old done, skipped and failed video jobs become retryable. This intentionally
  reruns video AI once: besides the no-keyframe fallback, consistent shared
  decoding changes the search input resolution. Existing valid photos do not
  rerun.
- **Virtualized Duplicates.** TanStack Virtual measures variable-height groups
  with stable keys, overscan and a resize-aware scroll origin. Preview and file
  reveal actions remain intact. Scrolling no longer accumulates earlier DOM.
- **Album statistics.** Each album's count and newest available cover are
  returned by one SQL statement, using the existing filter and read snapshot.
- **Consistent service arguments.** Album membership now takes asset ID first,
  album ID second, like asset tagging. The service, generated bindings, bridge,
  details-panel caller and contract test agree.
- **Localized validation.** Eight specific album validation codes replace
  parsing English error messages. Wrapped errors preserve `ErrInvalidAlbum`;
  the UI maps every code to typed translation keys, with a localized fallback.
- **Blocked named searches.** People, Things, places and albums are matched
  together using Unicode whole words, longer-name precedence and blocked
  precedence for exact ties. Repeated longer names cannot expose a shorter
  blocked name. Only matched visible people narrow the photo search.

## Second review round

A second end-to-end review covered this branch's changes against `main`, and
the code they touch. Seven parallel reviewers each took one area: store,
indexing/AI/people, media/platform, search/services, frontend core, frontend
views, and cross-cutting contracts and docs. Every finding was checked against
the code before it was fixed, and each fix has a regression test.

### Fixed

**Privacy**

- **Search kept hits that became hidden.** A face that joins a photo-blocked
  person during indexing used to leave that photo in the open search.
  Search results now prune themselves in place on any asset change, through
  the new `SearchService.VisibleAssets`. Order is kept, and the search isn't
  re-run.
- **Lists could show blocked items again.**
  - A list read still in flight when a block was made installed its
    pre-block answer afterwards.
  - Duplicates wasn't refreshed by blocks at all.

  `defineCollectionStore` now has `invalidate()`, which clears the cached
  entries and supersedes pending reads. `showBlocksChanged` invalidates every
  list that is loaded or loading: Things, People, Albums and Duplicates.
  Duplicates is back on the shared store.
- **The Blocked list stayed on screen after the engine relocked it.** After
  ten idle minutes, or a `blocks_locked` answer, the view now clears the list
  and shows the PIN form again. The idle time is mirrored in the bridge and
  checked by the contract test.
- **Smaller fixes:**
  - An open Duplicates preview closes when its photo disappears.
  - The album editor resets when its album is blocked or removed.

**Upgrades of existing libraries**

- **Face output changed without a version change.** The resample fix changed
  the detector's input for photos smaller than it, and the HEIC colour fix
  changed decoded pixels.
  - `FaceAnalysisVersion` is now 3.
  - Analysis-2 faces stand where the photo is at least the detector's size
    and decodes as it did before the colour fix (`facePixelsStand`).
  - Jobs carry their stored size, so blocked photos are judged the same way.
  - Only affected photos rerun.
- **Date rule changes never reached indexed files.** Videos now accept
  pre-1970 dates, and exact Unix and QuickTime epochs are rejected for photos
  and videos.
  - Both metadata versions are bumped.
  - Videos re-read their metadata.
  - A photo's metadata stands (`metadataStand`, `MetadataResult.Unchanged`)
    unless its stored date is an epoch.
  - A rejected EXIF date falls back to the scanner's guess, from the file
    name or file time across the photo's copies.

**Indexing and search**

- **One failing video model starved the other stage.** Embedding and face
  failures now back off separately (`stageBackoff`, shared with the photo
  stages). Only the failed model is released.
- **An interrupted Thing creation missed photos for good.** `CreateLabel` now
  stores the Thing's vectors only after scoring commits, as `loadLabels` does.
- **Clustering ignored cancellation** in its cached-link path and its
  person-pair loop.

**Performance**

- **Video job fetches scanned the whole photo backlog** (about 0.3 s each at
  300,000 jobs). Migration 0017 stores each job's media kind, with a
  kind-keyed pending index. An empty fetch now takes under 1 ms.
- **`RemoveSource` regressed to one UPDATE per file.** `markOrphans` is a
  single statement again.
- **A pasted query of thousands of repeated names was quadratic.** Queries are
  cut to `search.MaxQueryRunes` before names are matched (`BoundQuery`).

**Frontend**

- **Thumbnails made during indexing didn't appear until a scroll.** This
  predates the branch. `triggerRef(days)` never reached the grid's getter
  watcher, which skips a callback for the same Map. `notifyDays()` replaces
  the Map, and the thumbs-only test now goes through such a watcher. A
  cancelled day read also released its in-flight entry too late, so it was
  never asked for again.
- **The details panel didn't refresh metadata** that arrived while it was
  open. It now does, without clearing an edit's error.
- **Settings saves:**
  - A failed slider save could roll back a newer value that was still
    debouncing (`latestSave.touch`).
  - Reopening Settings made a second save queue, so an older value could
    land last. The queues now live in the library store.
- **Person rename errors** survive background reloads (`actionError`, as in
  Events).

**Consistency**

- **Name length is now counted the same way.** Every name input checks the
  length in code points after trimming (`shared/names.ts`), as Go's
  `cleanName` does. `maxlength` counted UTF-16 units.
- **Album membership is asset-first in the store too,** matching `TagAsset`,
  the service and the bridge.
- **One source of truth for each rule:**
  - `core.DefaultDataDir` gives the instance ID and the paths one definition
    of the user's library.
  - `search.BoundQuery` is the one query cut.
  - `scanJob` is the one JobItem scanner.
  - Version history constants are named (`media.EpochDatesMetadataVersion`).
- **The date guessing moved to `core`** (`GuessDate`, `FilenameDate`,
  `Plausible`), so the store no longer imports the cgo media package.
- **Smaller fixes:**
  - An explicit `LUMEN_DATA_DIR` that names the user's library gets the
    default single-instance ID.
  - A log rotation that can't rename truncates instead of growing without
    bound.
