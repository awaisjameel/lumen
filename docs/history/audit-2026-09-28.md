# Implementation audit — 28 September 2026

Historical phase 1–4 snapshot. See the [current follow-up audit](audit-2026-09-28-current.md)
for the subsequent album implementation, additional repairs and fresh verification.

The phase 1–4 implementation was reviewed across startup, SQLite migrations and
queries, sources and watching, durable indexing stages, media serving, AI/search,
people corrections, generated Go/TypeScript contracts, Vue state and views,
dependency setup, quality checks and Windows builds. Confirmed defects were
repaired locally. This records the evidence for that scope; it does not certify
every device, codec or library size.

## Findings and repairs

| Area | Defect | Repair |
| --- | --- | --- |
| Source registration | Concurrent parent/child additions could both pass the overlap check. | Check existing sources inside the same write transaction that inserts and absorbs sources. |
| People corrections | Clustering computed before a user rejection could reassign or merge the rejected identity afterward. | Recheck rejections inside the assignment/merge transaction, in both merge directions. |
| Search eligibility | Removed or disabled assets could compete for top results and determine the relative cutoff, suppressing visible matches. | Apply the store's visibility predicate before ranking image and video vectors. Keep vectors available for restoration. |
| Video tags | New labels and vocabulary updates did not consistently use the strongest sampled moment used during initial indexing. | Share strongest-score aggregation and deterministic tie ordering; score sampled frames on label creation and retagging. |
| Upgrade recovery | A vocabulary version was recorded before labels and retagging completed. | Record completion only after the load succeeds, allowing interrupted upgrades to retry. |
| Reconciliation | An unreadable subtree could be mistaken for deleted files; deletion of a directory with a dotted name could be ignored as an unknown file type. | Preserve known entries on access failures and reconcile the parent of missing unknown-extension paths. |
| Historical dates | Negative timestamps from valid pre-1970 capture dates were discarded. | Treat zero as the missing-date sentinel and retain negative capture timestamps. |
| Timeline/search state | Old responses could overwrite a new scope, including A → B → A navigation; refreshes during reads could be lost. | Use request generations and revisions, per-request ownership of day loads, and a coalesced follow-up refresh. Surface load failures in the view. |
| Viewer | A preview could cover a playing video; native playback could count a search offset twice; a delayed neighbour lookup could reopen a closed viewer. | Limit previews to images, distinguish native and converted clocks, and verify viewer identity before applying navigation results. |
| Detail/people views | Responses, edits and errors could be applied to a different current selection. | Clear old state and guard asynchronous completion against the requested identity. |
| Lists/settings | Reloads requested during an existing read could be lost; leaving Settings before its debounce expired could discard a confidence change. | Queue a follow-up list read and flush pending confidence changes when leaving. |

## Consistency and maintenance

- Centralized the video-frame stage version used by scheduling and persistence.
- Removed a generic Vue ref assertion using `shallowRef<T[]>`, retaining strict
  generated contracts at the bridge boundary.
- Added 12 frontend regressions across the library store, viewer, shared list
  store and settings. Vitest, Vue Test Utils and jsdom are development-only
  dependencies, pinned in the lockfile; tests run in the existing quality gate.
  Their selected releases satisfy the repository's seven-day minimum age.
- Added Go regressions for source concurrency, stale clustering, search
  visibility, video tagging, upgrade recovery, historical dates and scanning.
- Documented Node requirements, test commands, generated-binding verification
  and the required ordering of frontend compilation and Go embedding.

## Existing-library effects

Metadata stage version 2 causes metadata to be read again so previously discarded
historical dates can be recovered. Vocabulary version 4 recomputes AI tags using
sampled video moments. Existing user tag edits retain precedence. These changes
do not require a new schema migration and do not modify source media.

## Remaining acceptance limits

- Native WebView2 interaction was not automated: the available desktop-control
  connection failed. Edge/server-mode playback plus a successful Windows build
  does not establish native-window, DPI, installer or shell-integration behavior.
- `TestFacesOnRealPhotos` and `TestIndexerFindsPeople` need an explicitly supplied
  real-person photo corpus. Existing synthetic/unit coverage and native AI tests
  passed; visual face-clustering acceptance on such a corpus remains outstanding.
- Full-library performance, removable-drive/permission changes, every supported
  codec and GPU/fallback configuration were not re-benchmarked in this audit.
- Albums, events, trash, organise-on-disk, cache-size enforcement and OCR remain
  planned later-phase work, as already recorded in the README and roadmap.

No remaining confirmed defect was found within the checks performed. The limits
above are the outstanding acceptance work before claiming exhaustive validation.
