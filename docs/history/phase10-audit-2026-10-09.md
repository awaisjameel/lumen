# Phase 10 staged audit and local repair

## Audit Summary

Audited `phase10/customisation` against HEAD
`9ed033028ccb9e2b52578404182c8284e7e0ee87`. The original index contains
69 changed files, 6,340 additions and 194 deletions. There were no initial
unstaged or untracked files. Repairs and this report remain unstaged.

The staged implementation covers the Phase 10 settings categories,
preference persistence and migration, shortcut overrides, format exclusions,
customisation files, export presets, viewer controls and cache management.
The audit traced core defaults and validation through SQLite, services,
generated bindings, bridge normalisation, stores, settings, command dispatch,
media consumers, native tests, build tasks and documentation. There is no
terminology migration; existing Settings instructions needed new section names.

The original staged snapshot passes its existing checks after generating
the embedded frontend, but fails supplementary regression probes. It retains
the defects below until the local repairs are included in a future patch.

## Findings

| Finding | Original behaviour | Local repair |
| --- | --- | --- |
| Concurrent format choices | Service-level read/modify/write loses exclusions. A probe setting ten formats concurrently retained only TIFF. | Store owns the entire mutation under `settingsMu`; rescan runs only after an actual inclusion change. |
| Format save failures | A recovery read can reject the queue permanently. An older failure also replaces newer optimistic choices with stale data. | Keep the last successful list, serialise mutations, and update visible state only for the newest request. No recovery read is needed. |
| Reset ordering | Engine saves and debounced confidence changes can finish after a reset; later preference edits can be replaced by its response. | Drain existing save queues, flush the confidence draft, serialise resets, and apply later edits after reset completion. Refresh persisted state even after partial reset failure. |
| Misleading save success | Import closes its preview and announces success after a failed save; preset creation discards the entered name. | Preference saves report success; import keeps its preview for retry and preset creation keeps its input on failure. Names discarded by the engine's Unicode matching are explained. |
| Essential shortcuts | A valid `viewer.close` override disables Escape. `Alt+f4` bypasses the reserved-key comparison. | Core normalisation discards Close overrides and checks Alt+F4 without case sensitivity. |
| Shortcut collisions | Reset restores keys already assigned elsewhere; the search action's `/` alias is absent from conflict checks. | Assignment and Reset share conflict validation; aliases use the command registry's existing override semantics and are checked against declarations. |
| Import boundaries | Missing/null preferences are accepted; differently cased shortcut fields merge rather than replace the stored list. | Require a preferences object and apply the decoder's case-insensitive field semantics consistently when replacing lists. |
| Build and instructions | The canonical npm task uses a mutable install, and documentation directs users to obsolete Settings sections. | Use `npm ci` and update the setup diagnostics, README, native-test instructions and beta guide. |

Supplementary probes on the isolated staged product code reproduced the
backend lost update and four frontend failures: false import success,
stale format rollback, a permanently rejected format queue, and shortcut
Reset collisions. The Escape regression also failed before its repair.

## Actions Taken

- Extended the existing Store, preference store, command registry and
  `latestSave` owners. No dependency, persistence schema or wire field was added.
- Added `latestSave.flush` so resets wait without writing another preference
  set. The library coordinates engine saves and preference resets; the
  preference store continues to own presentation state and its save queue.
- Added regression coverage for concurrency, retry, stale responses, reset
  ordering and partial failure, import validation, reserved shortcuts,
  alias conflicts and engine-normalised preset names.
- Regenerated Wails bindings through the canonical command; there is no
  generated drift or lockfile change.

## Cleanup

Removed the service's unlocked format-list mutation, the failure recovery
read, duplicate shortcut collision checks, the obsolete UI-only engine
section list and the redundant preference write before reset. Updated
related descriptions and setup diagnostics. New comments explain queue
ordering and failure ownership. No compatibility path or testing rule was removed.

## Second review, after the commit

A further review of `9ed0330..cf6733c` (the committed Phase 10, with the
repairs above) found no data-loss or safety defect. It changed the
following, all local and uncommitted.

| Finding | Change |
| --- | --- |
| A failed format choice could go unexplained | The formats are separate choices, but only the newest save reported a failure: turning RAW off (fails) and then HEIC off (saves) put RAW back with no reason given. A failed choice is now always explained; the newest to finish still shows what the library holds. |
| Resetting a shortcut could bring back a taken alias | Reset gave search its `/` back even when another action had since been given `/`. Assigning and resetting now share `assignmentConflict`, which checks an action's other keys too. |
| The reset of excluded formats read, then wrote | `resetIndexing` read the list outside the settings lock before clearing it. The store now changes the list in one locked step (`changeExcludedFormats`), which `SetFormatExcluded` and the new `ClearExcludedFormats` share; `SetExcludedFormats` is gone. |
| Reset ordering was written twice | The preference store and the library store each kept their own chain of pending resets. Both use `shared/turns.ts` now. |
| Three ways into one preference save | `set`, `setViewer` and `setShortcut` each waited for the load and for resets before calling one another. They are one `change`. |
| Enum lists rebuilt in three views | The bridge's mirrored lists (`EXCLUDABLE_FAMILIES`, `START_VIEWS`, `PREF_CATEGORIES`) were plain names that each view mapped back to the generated enum. The bridge now exports them as the enum's members; the contract test reads the same names. |
| Eight copies of a section heading | `settings/SectionHead.vue` is the heading, its Reset and its note; reset notes are keyed by `PrefCategory`. |
| Preview names could miss a preference | The names a customisation preview shows are typed by every key of the preferences, so a new preference without a name fails the type check. |
| Customisation file read four times | It is read as a head, the names present, and one strict decode over the library's own preferences. |
| Save dialogs and atomic saves repeated | `chosen` and `publishFile` (in `services/library.go`) serve the folder picker, the problem report and the customisation file. |
| Unnamed limits | The shortcut id bound and the viewer's fixed Close are named constants in `core`. |
