# Staged Places and Events Audit - 30 September 2026

## Verdict

All six confirmed findings are fixed and verified. The follow-up also resolves
the local loader duplication, concurrent event-cache misses, thumbnail-driven
regrouping, unconstrained group routes and unsupported npm release-age setting.
The original findings and verification below are retained as historical evidence;
the current resolutions and follow-up verification record the fixed behavior.

Original review scope: all 35 staged files (1,425 insertions, 14 deletions), covering Places and
Events from the bundled geographic dataset through metadata indexing, SQLite
migrations, grouping/cache invalidation, Wails services/generated types, the
bridge, routes, views, shared cards, settings and documentation. Nearby owning
code and existing regression tests were reviewed where needed. This was not a
new line-by-line review of every unchanged subsystem.

The initial audit did not modify production code, and its temporary probes were
removed. The follow-up fixes now include permanent regression tests and migration 0013. Changes are left unstaged for review; no commit or restaging was performed.
Runtime fixtures, the CDP script, screenshots and race-test output are in the
ignored audit directory `bin/audit-20260930/`. The scratch app exited cleanly
after the production acceptance run. User library data was not used or modified.

## Resolutions

| Finding                         | Resolution                                                                                                                                                                                                                                                                                                                                            |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Superseded settings failures | Gap writes are serialized and coalesced to the newest queued value. Request revisions suppress stale errors; failed latest writes roll back to the last persisted value. Numeric normalization and queued writes after unmount are tested.                                                                                                            |
| 2. Superseded event names       | Rename/reset resolves membership while holding the writer transaction. Rename assigns the replacement to every current member; reset clears every current member's name. Tests cover merging, splitting, earlier imports, retiming and anchor removal.                                                                                                |
| 3. Dropped event filters        | One `assetFilter` composes the resolved event with favourites/videos/tag/person/place. Tests cover actual bucket and day-item queries.                                                                                                                                                                                                                |
| 4. Unbounded event queries      | Indexed coarse time bounds accompany exact timestamp/ID boundaries. A regression asserts `SEARCH assets USING INDEX assets_timeline (taken_at>...)`; equal-timestamp membership remains exact.                                                                                                                                                        |
| 5. Repeated backfill scans      | Migration 0013 adds `assets_pending_place`, a shrinking pending-GPS partial index. Batch updates use a prepared statement and deduplicate city inserts. Tests verify the plan, cancellation, committed batches surviving a transient failure, and resumed/idempotent completion. The indexer reports partial committed progress and retries failures. |
| 6. Stale timeline headings      | Coalesced title reads follow relevant library changes and route changes, with route/unmount guards. Component regressions and the production WebView2 run verify live updates.                                                                                                                                                                        |

Event names belong to the members visible when the user renames the group. Those
members retain the replacement after splitting, retiming or removal of the oldest
member. Newly joining media inherits a name while grouped with named members;
it receives a persisted name if included in a later rename. Reset applies to the
current visible group, not unrelated hidden or split members. This avoids reviving
superseded names without changing original media or freezing automatic grouping.

Additional corrections:

- Places, Events and existing list stores reuse one coalesced list-state owner.
  Component disposal prevents queued reads and late results from changing state.
- Event-cache misses are serialized. Revisions and grouping come from one read
  snapshot. Cover-only updates use bounded probes through `assets_event_cover`
  rather than rebuilding membership. Returned arrays remain isolated copies.
- Group-card routes are restricted to `place` or `event`. Rename controls cannot
  open another editor while saving.
- Event-gap settings use a shared validated integer reader and integer storage
  across views and services; existing integer-valued settings remain compatible.
- npm now uses the supported `min-release-age=7`, measured in days, with strict
  Node/npm engine checks and npm 11.19+ required. No dependency versions changed;
  the lockfile change only mirrors the new root npm engine requirement.

## Original Findings

### 1. P2: Older failed settings writes overwrite newer successful values

Location: [SettingsView.vue](../../frontend/src/settings/SettingsView.vue#L73).

`setEventGap` captures the previous value independently for each request and
unconditionally rolls it back on failure. It neither serializes saves nor checks
whether a newer request has superseded the failed request.

Confirmed in a component probe: start a pending save of 24 hours, successfully
save 36 hours, then reject the first request. Both the reactive setting and the
input revert to 12 even though the newer engine save succeeded. This can leave
the displayed setting inconsistent with actual event grouping.

Correction: serialize/coalesce setting writes and only apply rollback/error
state for the current operation. Add a deferred-response regression test.

### 2. P2: Renaming a merged event leaves superseded names behind

Location: [events.go](../../internal/store/events.go#L211), with name selection at
[events.go](../../internal/store/events.go#L105).

Automatic grouping inherits the first stored name on any visible member, but a
non-empty rename only upserts the current anchor. Names from other members of a
merged group remain. Reset already deletes all names in the current group, so
rename and reset have different ownership semantics.

Confirmed: separately name two events 13 hours apart, merge them with a 24-hour
gap, rename the merged event, then hide its current anchor. The remaining event
displays the old second-event name rather than the merged replacement. Source
removal or metadata retiming can expose the same stale-name state.

Correction: define name ownership across regrouping, and reconcile superseded
names transactionally when renaming. Include merge, rename, split, retiming and
anchor-removal coverage. If restoring earlier names is intentional, document
that policy explicitly and test it instead of leaving it accidental.

### 3. P2: Event views silently discard other view filters

Location: [library.go](../../internal/store/library.go#L61).

The event branch creates `assetFilter{event: &event}` and returns before applying
the requested favourites/videos filter, tag, person or place. Unlike albums,
events are not documented as exclusive of other filters. Place views compose
with the other filters, making the new view contracts inconsistent.

Confirmed with two assets in one event, only one marked favourite:
`DayBuckets(View{Filter: FilterFavourites, Event: id}, ...)` returns count 2.
Current event routes request only an event; the defect is in the shared service
contract and affects callers that compose the typed view fields.

Correction: construct one filter and add the resolved event boundary to it.
Alternatively make exclusivity explicit and reject conflicting input. Test
event-plus-favourites/videos/tag/person/place contracts.

### 4. P2: Single-event bucket queries scan the entire visible timeline

Location: [library.go](../../internal/store/library.go#L131).

The OR-expanded lexicographic boundaries do not give SQLite a bounded range
access path for `DayBuckets`. The production-driver plan on 100,000 assets was:

```text
SCAN assets USING INDEX assets_timeline
USE TEMP B-TREE FOR GROUP BY
```

This occurred even for a boundary selecting one asset. A comparable explicit
`taken_at >= ? AND taken_at <= ?` predicate produced:

```text
SEARCH assets USING INDEX assets_timeline (taken_at>? AND taken_at<?)
```

Correction: supply indexable coarse time bounds while retaining exact timestamp
and ID tie-breaks, or verify indexed tuple comparisons. Assert the access plan
with realistic data and test equal-timestamp boundaries. Repeated event refreshes
must not become full-library scans.

### 5. P2: Upgrade backfill repeatedly rescans processed asset prefixes

Location: [places.go](../../internal/store/places.go#L35), with indexes introduced by
[0010_places.sql](../../internal/store/migrations/0010_places.sql#L11).

Every 500-row batch starts again at the beginning of `assets` with
`place_checked = 0`. There is no matching index or keyset cursor. The confirmed
plan is `SCAN assets`; the visible-place index cannot serve this predicate.
As more rows become checked, each subsequent batch walks past the processed
prefix again. For an all-GPS library, selection work grows approximately
quadratically with asset count at a fixed batch size.

Correction: use a resumable pending-GPS partial index or a per-pass ID cursor,
preserving independent batch commits and metadata-write guards. Add a query-plan
test, cancellation/resume coverage and an upgrade benchmark.

### 6. P3: Mounted event headings do not follow library changes

Location: [LibraryView.vue](../../frontend/src/library/LibraryView.vue#L75).

The group-title watcher depends only on place/event route IDs. Timeline data
refreshes after library changes, but the title is never re-fetched. Metadata or
place backfill can change an event's automatic date/place title without changing
its route ID.

Confirmed in the native production app: load an event timeline, change its name
through the real service and dispatch an assets-change notification. The timeline
reloads and `Event(id)` returns the new name, but the heading retains the old one.

Correction: invalidate/reload event titles with the relevant library changes,
using latest-request and unmount guards. Test a metadata-driven title change
while the same event route stays mounted.

## Original Consistency And Residual Risk

- Good foundations: generated Go/TypeScript wire models, nil-list normalization
  at the bridge, constant drift checks, shared cards, bound SQL values, offline
  hash-pinned data, read-snapshot event grouping and visibility-aware counts.
- Places and Events duplicate their request-generation/loading logic rather
  than reusing the existing `coalescedLoad` utility. Stale results are suppressed,
  but overlapping requests still run. Cold concurrent event-cache misses can
  likewise duplicate full regrouping work.
- Thumbnail revisions invalidate the entire event grouping even though they
  affect covers, not membership. The 100k measurement above makes this an
  explicit optimization opportunity; separate cover refresh from membership
  invalidation before making million-asset responsiveness claims.
- `GroupCard.route` is an unrestricted string, not a constrained group-route
  type. Static typing passes, but it does not prove all route/ID combinations
  are valid. Avoid equating a green typecheck with runtime contract correctness.
- Existing debt in the previous audit remains: superseded bridge calls are not
  cancelled, native decodes are not cancellable, and some request/lifecycle
  implementations remain duplicated. This change does not eliminate that debt.
- npm warns that `minimum-release-age` is an unknown project configuration.
  The documented dependency-age policy is therefore not enforced by those npm
  invocations. This is inherited configuration, not introduced by these staged
  files.
- Not exhaustively verified: disk-full/transient-failure recovery during place
  backfill, every cache/write interleaving, huge event-list DOM costs, arbitrary
  media, real-world face accuracy, unplug/replug, accessibility with assistive
  technology, DPI combinations and packaging. Existing tests and the native
  smoke test are evidence for their exercised cases, not universal guarantees.
