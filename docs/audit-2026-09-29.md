# End-to-end audit — 29 September 2026

Scope: everything implemented through phase 5 (library, search and Things,
people, videos, albums, duplicates), Go engine to Vue UI. Six areas were
reviewed file by file in parallel (store and core; indexer, scanner and
startup; media and native decoding; AI, search and people; the service and
bridge contract; the frontend). Every finding below was checked against the
code before it was fixed. The earlier reports ([28 September](audit-2026-09-28-current.md))
remain the record of what was fixed then.

The baseline was green (lint, 21 frontend tests, the Go race suite), so
nearly everything here was found by reading and tracing, not by failing
checks. Three things are worth knowing first:

- **Converted video could not stream in the real app.** On Windows, Wails
  gives WebView2 a response only once it is complete. Converting an AVI
  therefore waited for the whole conversion, held in memory. Seeking a large
  MP4 read the whole file first. The earlier acceptance run used Wails'
  server mode, where real HTTP hides this. Videos now stream from a
  loopback-only server (below), and the check now runs in WebView2 itself.
- **iPhone and other wide-gamut photos had dull thumbnails.** Display P3
  and Adobe RGB values were read as sRGB. This affected the AI's input too.
- **Case-insensitive names worked for A–Z only.** SQLite's `NOCASE` and
  `LIKE` fold ASCII only. "Émile" and "émile" became two people, suggestions
  missed accented names, and "İbrahim" could crash a search.

### Indexer, scanner and startup

- A second copy of Lumen opened and migrated the database, and loaded the
  AI, before Wails' single-instance check. The app is now created first, and
  services are registered after it.
- `ServiceStartup` blocked the window on requeueing and on opening a watcher
  for every source (an offline network share takes the SMB timeout). That work
  now runs in the background.
- A watcher that failed (drive unplugged, share gone) stopped for good. It
  now retries with backoff and rescans once it runs again.
  `ERROR_NOTIFY_ENUM_DIR` counts as an overflow, and 8.3 short names are
  expanded.
- Concurrent `RescanAll` calls could leave watchers for the old list; they
  are now serialised. The debounce waits at most 30 s, so a video being
  recorded no longer delays every rescan.
- A failed settings read scanned with videos off, which marked every video
  missing; the scan is now retried. `embedVideo` had no panic recovery. A
  model that failed to run stayed loaded and failed every minute with no UI
  signal; it is now released, retried with backoff (up to 10 minutes), and
  its error shown in Progress.
- The scanner:
  - follows a source that is itself a junction or symlink (such as a moved
    Pictures folder);
  - skips hidden and dot files (macOS `._` files), symlinked files, and
    watcher changes inside folders a full scan skips (recycle bin, `.git`);
  - fingerprints with `FILE_SHARE_DELETE`, so Explorer can still rename a
    file while it is being hashed.
- Progress polling adapts to how long counting takes. Stage versions are
  built in one place. `library:changed` now says what changed (`core.Changes`:
  assets, tags, people), so the timeline no longer reloads every second
  while only the AI works.

### Media

- **Video streaming:** `services.Streamer` serves `/video/{id}` (the file,
  with Range) and `/play/{id}?at=` (converted). It listens on 127.0.0.1 only,
  with a random secret in every path and a Host check. `ConvertMP4` probes
  before any header is sent, so a damaged file gets an error status instead
  of an empty 200.
- **Colour:** libvips converts from embedded ICC profiles to sRGB, after
  shrinking (`testdata/red-p3.jpg` guards it). WIC applies HEIC profiles
  before scaling (WIC can't convert a scaler's output). Thumbnails re-run
  once (`ThumbnailVersion` 2).
- **Pixels, frames, dates and sizes:**
  - BMP alpha is straight, no longer premultiplied twice.
  - The full frame pass counts from the stream's start time.
  - ffmpeg log lines up to 4 MiB are read; captured stderr is capped.
  - EXIF modify dates are no longer capture dates.
  - The image header's size wins over EXIF's (crops).
  - One plausibility check covers dates from EXIF and from file names.
- **Cache:**
  - Rebuild locks can be cancelled.
  - A frame is decoded without holding the lock the indexer writes under.
  - Temporary files go to one folder, swept at startup.
  - Empty files count as missing.
  - Frames are kept per code version.
  - libvips errors are copied and cleared atomically.
- **Routes:** unknown sizes and extra path segments get 404; content types
  come from Lumen's own table; cache headers are consistent; unexpected
  failures are logged.

### AI, search and people

- Face yaw was measured along the image x-axis, so a tilted face that looks
  at the camera counted as turned. It is now measured along the eye axis.
  Sharpness ignores the black beyond the photo's edge. Faces re-run once
  (`ai.FaceAnalysisVersion`).
- One NaN vector from the GPU failed the whole batch forever. Unusable
  vectors are now per image (`ai.Normalise`), and the scan drops NaN scores.
- Clustering re-checks "two faces in one photo are never one person" when it
  applies its changes, against every face. A run could previously use a
  snapshot that the user had changed since, or one missing hidden photos.
- The Linker drops links to faces no longer present, avoids duplicate
  links, and can be cancelled at shutdown.
- The search engine:
  - can't reopen the text model after `Close`;
  - no longer lets the idle unload free a model that was just used;
  - caches the set of unavailable assets;
  - ranks videos by their moments only;
  - caps queries at 500 characters and pre-cuts the tokenizer's input;
  - reads each model's input and output names once, unoptimised, instead of
    building every model twice on each load.
- `CreateLabel` cleans up with a context that can't be cancelled. It also
  makes a Thing the user tagged by hand into one the AI looks for.

### Services and bridge

- **Typed errors:** failures reach the UI as `{"code": ...}` (`services.ErrorCode`,
  via Wails' `MarshalError`). The UI explains known codes in its own words.
  Naming someone with a taken name now asks "same person?" on
  `person_exists`, with no lookup first.
- **Search without the AI:** it returns people's photos and says what it
  couldn't do (`SearchResult.NoAI`), instead of failing.
- **Validation:** `AddSources` checks every folder before adding any.
  Cancelling the folder picker returns "", not an error.
- **API:** `ShowInFolder(id, path)` replaces two methods.
- **Drift checks:**
  - Event names are typed against the generated event map.
  - `services/contract_test.go` checks every constant and error code the
    bridge mirrors.
  - ESLint allows the bindings to be imported only from the bridge.

### Frontend

- **Keyboard:**
  - The viewer listens in the bubble phase. The seek slider and video
    controls keep their arrow keys, and a picker closing its menu keeps
    Escape.
  - "/" and Ctrl+F wait while a modal is open.
  - The seek slider no longer jumps back while it is dragged.
- **The viewer as a modal:** it moves to `<body>` and makes the page behind
  it inert, has an accessible name, and closes when its grid unmounts.
- **Stale and lost state:**
  - Welcome no longer flashes "no folders" or drops a folder picked early.
  - Checkboxes are put back when a change fails.
  - PersonHeader shows its errors and clears them.
  - List errors clear on the next successful load.
  - Things no longer navigates after the user has left.
- **Loading less:**
  - Startup loads the timeline once. The timeline loads only while a grid
    shows it.
  - The viewer mounts one Details panel, not two.
  - A day already loading is waited for rather than dropped.
  - Favourites roll back correctly.
  - Face thumbnails are lazy `<img>`s, and face tiles use
    `content-visibility`.
  - The scrubber no longer re-observes itself on every scroll.
- **Consistency:**
  - Shared cards, fields, the subtle button (which had never been defined),
    notices, and colour tokens that pass contrast in both themes.
  - Confirmation before deleting a Thing or removing a folder. The dialog
    focuses Cancel.
  - Every visible string goes through `t()`, including shortcut hints,
    separators and sizes (`Intl`).
  - Accessible names for icon buttons and grid cells.
  - `<main>` landmark; quieter progress announcements.
  - "Yesterday" is safe across daylight-saving changes.

## Compatibility

- Migration 0007 runs once on start: an index, and a column filled from
  `assets` (a single `UPDATE`). There is no rollback path, as with earlier
  migrations.
- Re-runs after the upgrade: every photo's metadata (dates), then
  thumbnails (colour; pHashes shift slightly, so similar-photo groups may
  change a little), then faces (yaw and sharpness). The faces stage matches
  new faces to the old ones, so names and corrections are kept. On a large
  library this is hours of background work, paused on battery as usual.
- Bound API changes: `CreateAlbum(..., items)`, `ShowInFolder(id, path)`,
  `MediaService.VideoBase()`, the `library:changed` payload and
  `SearchResult.noAI`. The bindings are regenerated.

## Not done, and why

- Commands on the UI side can't cancel engine calls yet: the bridge wraps
  Wails' `CancellablePromise` in plain promises. Superseded searches and
  suggestions finish in Go and are then dropped. This is worth doing along
  with a request-scope helper.
- The two comboboxes (search box, person picker) still duplicate their key
  handling and menu styles. A shared `useCombobox` is the next cleanup; they
  behave correctly today.
- Details still makes four calls per selection (asset, tags, faces, albums).
  One `AssetInfo` call would halve the requests. Titles still load whole
  lists to show one name.
- search.Engine and index.model keep separate load-on-demand lifecycles.
  Unifying them into one `Lazy[T]` in `internal/ai` is a refactor with no
  behaviour change.
- WIC starts COM once per image, and a video is probed by ffprobe once per
  stage. Both are unmeasured costs, left until they are measured.
- libvips decodes can't be cancelled (a pathological PNG ties up a worker).
- Accepted by browser automation of the real WebView, not by hand: DPI,
  installers, codec and GPU combinations, and drive unplug/replug. The
  retry paths are covered by tests only. Face-identity accuracy after the
  yaw change was not re-measured on a real-person corpus (none supplied).
